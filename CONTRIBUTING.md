# Contributing Guide

Thank you for your interest in contributing to the JavaScript 600 Club project.

This document explains the workflow, standards, and guidelines for contributing to this repository.

---

## Getting Started

Before contributing, please:

1. Read the repository README.md
2. Check available issues
3. Understand the project structure
4. Follow the contribution workflow

---

## Contribution Workflow

Follow this workflow when making changes:

1. Create or select an issue
2. Create a new branch from `main`
3. Make your changes
4. Commit your changes
5. Push the branch
6. Create a Pull Request
7. Wait for review and merge

---

## Branch Naming Convention

Use meaningful branch names.

Format:

```
type/description
```

Examples:

```
feature/add-array-solutions
docs/update-readme
fix/fix-validation-error
refactor/improve-solution-structure
```

---

## Commit Message Convention

This project follows Conventional Commits.

Format:

```
type: short description
```

Examples:

```
feat: add array problem solutions
fix: correct loop solution
docs: update contributing guide
refactor: improve folder structure
```

---

## Issue Guidelines

Before starting work:

- Check if an existing issue already exists
- Create a new issue for new tasks
- Add proper labels and milestone
- Assign the issue to yourself before working

---

## Pull Request Guidelines

A Pull Request should:

- Have a clear title
- Link the related issue
- Explain the changes
- Include testing information
- Follow the PR template

Example:

```
Closes #10
```

---

## Problem Solving Guidelines

For JavaScript problems:

- Understand the problem before coding
- Write clean and readable code
- Test solutions before submitting
- Avoid unnecessary complexity
- Add explanations when needed

---

## Code Style

Follow these practices:

- Use meaningful variable names
- Keep functions small and focused
- Maintain consistent formatting
- Write readable JavaScript

---

## Review Process

Every Pull Request should be reviewed before merging.

Reviewers should check:

- Code quality
- Logic correctness
- Repository standards
- Documentation updates

---

Thank you for contributing and helping improve this project.
